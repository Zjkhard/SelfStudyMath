# 多位数加法与减法

我们已经会计算万以内的加法和减法。

多位数的数位更多，但基本关系没有改变：

~~~text
相同数位上的数量才能直接相加或相减
10 个较小单位可以组成 1 个相邻的较大单位
1 个较大单位可以分成 10 个相邻的较小单位
~~~

今天，我们把这些方法扩展到百万以内的数。

## 一、多位数加法表示数量合并

看：

~~~text
243,586 + 152,749
~~~

243,586 和 152,749 是两个部分。

把两个部分合起来，得到它们的和：

~~~text
243,586 + 152,749 = 396,335
~~~

加法中的数量关系是：

~~~text
部分 + 部分 = 整体
~~~

多位数加法仍然是在合并相同位值的数量：

~~~text
个位和个位合并
十位和十位合并
百位和百位合并
……
~~~

## 二、多位数减法表示数量分离或比较

看：

~~~text
732,406 - 218,759
~~~

可以表示从 732,406 中取走 218,759，也可以表示两个数相差多少。

结果是：

~~~text
732,406 - 218,759 = 513,647
~~~

减法中的数量关系可以表示为：

~~~text
整体 - 一个部分 = 另一个部分
~~~

或者：

~~~text
较大数 - 较小数 = 两数的差
~~~

## 三、先根据位值选择方法

计算前，可以先观察数字的结构。

如果只有整万、整千等单位发生变化，可以心算：

~~~text
340,000 + 25,000
~~~

34 个万加 2 万 5 千：

~~~text
340,000 + 20,000 = 360,000
360,000 + 5,000 = 365,000
~~~

所以：

~~~text
340,000 + 25,000 = 365,000
~~~

再看：

~~~text
780,000 - 60,000
= 78 个万 - 6 个万
= 72 个万
= 720,000
~~~

当数的结构适合心算时，不一定要写竖式。

## 四、用分解进行加法

看：

~~~text
324,150 + 213,420
~~~

按位值分解：

~~~text
324,150 = 300,000 + 20,000 + 4,000 + 100 + 50
213,420 = 200,000 + 10,000 + 3,000 + 400 + 20
~~~

合并相同单位：

~~~text
300,000 + 200,000 = 500,000
20,000 + 10,000 = 30,000
4,000 + 3,000 = 7,000
100 + 400 = 500
50 + 20 = 70
~~~

再合起来：

~~~text
500,000 + 30,000 + 7,000 + 500 + 70
= 537,570
~~~

所以：

~~~text
324,150 + 213,420 = 537,570
~~~

## 五、用补偿进行加法

有些数接近整万数或整十万数，可以先凑整。

看：

~~~text
398,750 + 26,480
~~~

398,750 距离 400,000 还差 1,250。

从 26,480 中拿出 1,250，补给第一个加数：

~~~text
398,750 + 1,250 = 400,000
26,480 - 1,250 = 25,230
~~~

总数没有改变：

~~~text
398,750 + 26,480
= 400,000 + 25,230
= 425,230
~~~

补偿法改变了两个加数的样子，但没有改变它们的和。

## 六、用补偿进行减法

看：

~~~text
525,000 - 198,700
~~~

198,700 接近 200,000。

先减去 200,000：

~~~text
525,000 - 200,000 = 325,000
~~~

刚才多减了：

~~~text
200,000 - 198,700 = 1,300
~~~

所以要加回 1,300：

~~~text
325,000 + 1,300 = 326,300
~~~

因此：

~~~text
525,000 - 198,700 = 326,300
~~~

补偿时，要先判断是多加、多减、少加还是少减，再做相反的调整。

## 七、竖式中的数位对齐

计算：

~~~text
482,615 + 7,930
~~~

写竖式时，个位必须和个位对齐：

~~~text
  482,615
+   7,930
---------
  490,545
~~~

可以用数位表检查：

~~~text
十万  万  千  百  十  个
  4   8   2   6   1   5
  0   0   7   9   3   0
~~~

7,930 前面没有写出的数位可以看成 0。

不能把数字只按左边对齐，因为那会把不同位值的数量放在一起。

## 八、一般的多位数加法

计算：

~~~text
243,586 + 152,749
~~~

竖式：

~~~text
  243,586
+ 152,749
---------
  396,335
~~~

从个位开始：

1. 个位：6 + 9 = 15，写 5，向十位进 1。
2. 十位：8 + 4 + 1 = 13，写 3，向百位进 1。
3. 百位：5 + 7 + 1 = 13，写 3，向千位进 1。
4. 千位：3 + 2 + 1 = 6。
5. 万位：4 + 5 = 9。
6. 十万位：2 + 1 = 3。

所以：

~~~text
243,586 + 152,749 = 396,335
~~~

每一次进位都表示 10 个低一位单位重新组成 1 个高一位单位。

## 九、连续进位

计算：

~~~text
586,794 + 278,658
~~~

~~~text
  586,794
+ 278,658
---------
  865,452
~~~

逐位计算：

~~~text
个位：4 + 8 = 12
十位：9 + 5 + 1 = 15
百位：7 + 6 + 1 = 14
千位：6 + 8 + 1 = 15
万位：8 + 7 + 1 = 16
十万位：5 + 2 + 1 = 8
~~~

一个数位上的进位会参与下一个数位的计算。

连续进位时，每一位都要检查有没有来自右边的进位。

## 十、三个数相加

多个加数也要按相同数位对齐。

看：

~~~text
128,450 + 76,325 + 9,870
~~~

~~~text
  128,450
   76,325
+   9,870
---------
  214,645
~~~

每一列可以同时把三个数位上的数量相加。

也可以分两步：

~~~text
128,450 + 76,325 = 204,775
204,775 + 9,870 = 214,645
~~~

两种方法得到相同的和。

## 十一、一般的多位数减法

计算：

~~~text
732,406 - 218,759
~~~

~~~text
  732,406
- 218,759
---------
  513,647
~~~

从个位开始：

1. 个位：6 不够减 9，需要从左边重新分解，得到 16 - 9 = 7。
2. 十位：经过重新分解后有 9 个十，9 - 5 = 4。
3. 百位：3 不够减 7，从千位分解 1 个千，13 - 7 = 6。
4. 千位：分解后剩 1 个千，1 不够减 8，从万位分解，11 - 8 = 3。
5. 万位：分解后剩 2 个万，2 - 1 = 1。
6. 十万位：7 - 2 = 5。

所以：

~~~text
732,406 - 218,759 = 513,647
~~~

退位不是把数字随意改小，而是把 1 个高一位单位重新分成 10 个低一位单位。

## 十二、跨过多个 0 的退位

计算：

~~~text
600,004 - 278,569
~~~

~~~text
  600,004
- 278,569
---------
  321,435
~~~

个位 4 不够减 9，但十位、百位、千位和万位都是 0。

需要从十万位的 6 中分解 1 个十万，并逐级向右重新分解：

~~~text
600,004
= 5 个十万
  + 9 个万
  + 9 个千
  + 9 个百
  + 9 个十
  + 14 个一
~~~

现在逐位相减：

~~~text
14 - 9 = 5
9 - 6 = 3
9 - 5 = 4
9 - 8 = 1
9 - 7 = 2
5 - 2 = 3
~~~

所以：

~~~text
600,004 - 278,569 = 321,435
~~~

连续的 0 表示这些数位原来没有单位，需要从更高数位逐级分解。

## 十三、末尾有 0 的减法

计算：

~~~text
450,000 - 86,725
~~~

被减数末尾有多个 0，需要从左边非零的数位逐级分解。

~~~text
  450,000
-  86,725
---------
  363,275
~~~

可以用加法检查：

~~~text
363,275 + 86,725 = 450,000
~~~

检查回到原来的被减数，说明结果符合加减法关系。

## 十四、用向上数求差

两个数比较接近时，可以从较小数向上数到较大数。

看：

~~~text
425,000 - 398,500
~~~

先从 398,500 到 400,000：

~~~text
增加 1,500
~~~

再从 400,000 到 425,000：

~~~text
增加 25,000
~~~

合起来：

~~~text
1,500 + 25,000 = 26,500
~~~

所以：

~~~text
425,000 - 398,500 = 26,500
~~~

从较小数增加到较大数，增加的总量就是两数的差。

## 十五、加法中的交换和组合

加数交换位置，和不变：

~~~text
125,000 + 48,600
= 48,600 + 125,000
~~~

三个数相加时，可以先组合容易凑整的两个数：

~~~text
175,000 + 86,400 + 25,000
~~~

先把 175,000 和 25,000 合起来：

~~~text
(175,000 + 25,000) + 86,400
= 200,000 + 86,400
= 286,400
~~~

选择容易凑整的顺序，可以简化心算。

减法通常不能随意交换前后两个数。

## 十六、连续加减要遵守顺序

看：

~~~text
420,000 - 138,750 + 26,300
~~~

加法和减法同级，要从左到右：

~~~text
420,000 - 138,750 + 26,300
= 281,250 + 26,300
= 307,550
~~~

如果情境要求先把后两个数合起来，需要用括号明确表示：

~~~text
420,000 - (138,750 + 26,300)
~~~

括号不同，数量关系和结果也会不同。

## 十七、用估算检查加法

检查：

~~~text
243,586 + 152,749 = 396,335
~~~

把两个加数四舍五入到最接近的万位：

~~~text
243,586 ≈ 240,000
152,749 ≈ 150,000
~~~

估算：

~~~text
240,000 + 150,000 = 390,000
~~~

准确结果 396,335 接近 390,000，数量大小合理。

如果结果误写成 39,633，就与估算相差很大，需要检查数位对齐或进位。

## 十八、用估算检查减法

检查：

~~~text
732,406 - 218,759 = 513,647
~~~

四舍五入到最接近的万位：

~~~text
732,406 ≈ 730,000
218,759 ≈ 220,000
~~~

估算：

~~~text
730,000 - 220,000 = 510,000
~~~

513,647 接近 510,000，所以结果的大小合理。

估算能发现明显错误，但不能保证每一个数字都正确。

## 十九、用减法验算加法

加法算式：

~~~text
243,586 + 152,749 = 396,335
~~~

从和中减去一个加数：

~~~text
396,335 - 152,749 = 243,586
~~~

或者：

~~~text
396,335 - 243,586 = 152,749
~~~

能够得到另一个加数，说明结果符合加法关系。

## 二十、用加法验算减法

减法算式：

~~~text
732,406 - 218,759 = 513,647
~~~

把差和减数相加：

~~~text
513,647 + 218,759 = 732,406
~~~

也可以从被减数中减去差：

~~~text
732,406 - 513,647 = 218,759
~~~

验算回到原来的数量，说明减法关系成立。

## 二十一、计算后进行完整检查

完成多位数加减法后，可以按顺序检查：

1. 数位是否对齐；
2. 运算符号是否看清；
3. 每一位的进位或退位是否处理；
4. 结果的位数和大小是否符合估算；
5. 能否用相反运算回到原来的数。

多种检查方法作用不同：

- 估算检查结果的大致大小；
- 相反运算检查准确的数量关系；
- 重新计算检查每个数位的过程。

## 二十二、容易混淆的地方

### 1. 不能只按数字左边对齐

竖式必须把个位和个位、十位和十位依次对齐。

### 2. 进位要加入下一位

某一位满十后组成的高位单位，要参加下一数位的计算。

### 3. 退位后原数位要少 1

一个高位单位分解成 10 个低位单位后，高位上的数量会减少 1。

### 4. 遇到 0 要继续向左寻找

当前数位是 0 时，需要从更高的非零数位逐级分解，不能跳过中间数位。

### 5. 估算结果不能代替准确结果

估算用于判断范围和检查合理性，需要准确答案时仍要完成精确计算。

## 二十三、小结

- 多位数加减法建立在十进制位值关系上。
- 计算前可以根据数字结构选择心算、补偿、向上数或竖式。
- 竖式中相同数位必须对齐，并从个位开始计算。
- 加法中某一位满十，要向相邻高位进 1。
- 减法中某一位不够减，要把相邻高位的 1 个单位分成 10 个低位单位。
- 连续进位时要把每一次进位加入下一位。
- 跨零退位时要从更高的非零数位逐级分解。
- 加数可以交换或重新组合，减法前后两个数通常不能交换。
- 连续加减属于同级运算，没有括号时从左到右计算。
- 可以用估算检查结果大小，用相反运算验算准确关系。
